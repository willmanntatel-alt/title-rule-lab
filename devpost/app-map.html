Title Rule Lab: where one check happens

This is a reference route through the actual implementation, not a claim that its participant completed a code tour.

  1. Edit a title — app.mjs, render()

    An input event clears the old export and requests a new analysis.

  2. Apply the entered rule — measurement.mjs, analyze()

    The selected count is compared with the validated integer limit. Overflow is marked using whole grapheme segments; the original text stays unchanged.

  3. Save the current record — app.mjs, build-report handler

    buildReport() assembles the exact current editor text and rule. The visible JSON and attachment link share the same serialized bytes.

To change this, start here

  • Counting definitions: measurement.mjs, measure().
  • Input validity: measurement.mjs, parseRule().
  • Labels and demo input: index.html and app.mjs.
  • Colors and spacing: styles.css.
  • Local download: server.mjs, /export route.

A practice to reuse

Write an observable example before coding: the same family-emoji title has 11 code points and 15 UTF-16 units. The corresponding test and browser result made a hidden assumption visible. Repeat that approach for any field whose “length” or “valid” definition is ambiguous.
